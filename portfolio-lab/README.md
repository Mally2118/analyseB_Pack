# Портфельная лаборатория

Приложение рассчитывает портфели по официальным месячным данным ЦБ, Росстата и Мосбиржи. Оптимизация использует **доходности сверх инфляции**. Денежная масса М2 — отдельный макропоказатель, в который нельзя вложиться; она исключена из весов, ковариации, кривых капитала и проверки.

## Запуск

```sh
npm install
npm start
```

Статическая версия находится в `dist/`; локальный сервер также предоставляет `/api/market-data`. При открытии приложение выбирает последние 60 опубликованных месяцев из официального снимка `dist/data/market-data.json`. В разделе «Данные» можно загрузить другой период: от 13 до 121 наблюдения. До успешной загрузки расчёт недоступен; при ошибке источников вымышленные данные не подставляются.

## Источники и состав

В исходном наборе 10 рядов: М2, золото, серебро, платина, палладий, USD, EUR, CNY, IMOEX и RGBITR. **Портфель содержит девять рядов без М2.** ИПЦ загружается из Росстата. М2 отображается в млрд рублей, валюты — в рублях за единицу, металлы — в рублях за грамм. IMOEX не учитывает дивиденды; RGBITR включает купоны. Дата каждого наблюдения — конец месяца. Пропуски не заполняются.

Источники, метод получения, дата загрузки и доступный период показаны в интерфейсе. На GitHub Pages используются настоящие опубликованные данные в снимке, который обновляет workflow в `.github/workflows`. Локальный сервер при выборе периода обращается к источникам напрямую. Сгенерированные Excel-примеры, генераторы и импорт произвольного Excel удалены. Синтетического индекса недвижимости в официальном наборе нет.

Обновление снимка с проверкой TLS-сертификатов:

```sh
node configure-rosstat-trust.mjs
NODE_EXTRA_CA_CERTS=artifacts/rosstat-ca.pem node update-market-data.mjs
```

Сбой обновления сохраняет последний проверенный официальный снимок и его исходную дату. Флаг `--strict` требует успешного обновления. `--output`, `--fallback` и `--diagnose-runner` используются workflow для кеша и диагностики. Проверка цепочки Росстата использует закреплённый отпечаток корневого сертификата; проверка TLS не отключается.

## Публикация GitHub Pages

Workflow публикует подготовленный каталог `artifacts/pages`, созданный командой `node prepare-pages.mjs`. HTML ссылается на JavaScript, CSS, библиотеки и шрифты внутри `assets/<хеш версии>/`. Относительные импорты модулей остаются в той же версии, поэтому кеш предыдущего деплоя не смешивает старый интерфейс с новым кодом. Только обновление статистики не меняет адреса кода. Данные остаются в `data/market-data.json` и загружаются с проверкой актуальности.

Перед упаковкой проверяются официальный снимок и наличие импортируемых модулей. Workflow дополнительно запускает тесты упаковки; повреждённый сайт не заменяет предыдущую публикацию. `build.json` содержит версию файлов и SHA коммита для диагностики.

## Расчёт

Для каждого из девяти активов:

`r_real,t = (P_t / P_(t-1)) / (CPI_t / CPI_(t-1)) − 1`.

Инфляция применяется один раз. Средняя месячная реальная доходность и выбранная оценка ковариации умножаются на 12; риск — квадратный корень из дисперсии портфеля. Номинальная годовая безрисковая ставка переводится в реальную: `(1 + nominalRf) / (1 + annualizedInflation) − 1`.

Четыре критерия: Марковиц `max μᵀw − λwᵀΣw`, максимум Шарпа `(μᵀw − rf) / sqrt(wᵀΣw)`, минимум риска при минимальной реальной доходности, максимум реальной доходности при ограничении волатильности. Веса в сумме равны 100%. По умолчанию они неотрицательны; режим «Короткие продажи» разрешает отрицательные веса с заданным минимумом. Максимум ограничивает длинный вес и модуль короткой позиции. Положительный минимум обязателен для каждого включённого актива. Исключённые активы имеют вес 0. Несовместимые границы отклоняются. Маленькая регуляризация стабилизирует решатель; показанный риск считается по исходной ковариации.

Капитал строится по реальным доходностям с ежемесячным восстановлением весов. Комиссии, налоги и спреды не включены. Доходности, ожидаемый доход и капитал выражены в покупательной способности на начало периода. CAGR отличается от ожидаемой арифметической доходности. Восстановление измеряется календарными днями от предыдущего пика; знак `≥` означает незавершённый срок.

## Интерфейс

Вкладки: «Портфель», «Графики», «Сравнение», «Проверка», «Данные», «Инструкция». Доступны ссылки `#portfolio`, `#graphs`, `#comparison`, `#backtest`, `#data`, `#help`, клавиатурная навигация, русский и английский языки, светлая и тёмная темы.

График инфляции переключается между месячной, год к году и накопленной с начала периода. Год к году требует предыдущих 12 наблюдений; отсутствующая история остаётся пустой. М2 отображается отдельно как объём денежной массы РФ.

Сравнение: текущий и до восьми сохранённых портфелей, разницы Δ относительно базы, подсветка лучших и худших значений, скрытие линии и удаление портфеля. Общий период пересчитывает показатели и кривые, сохраняя веса. Именованные наборы хранятся в браузере в формате v2 с девятью инвестиционными весами и официальными исходными данными. Старый формат с инвестиционной долей М2 не принимается. Новая загрузка сбрасывает текущее сравнение и проверку.

Во вкладке «Проверка» веса определяются только на обучении и применяются на следующих датах; ставка Шарпа корректируется по инфляции обучения. В каждой части нужны минимум 12 периодов. Ориентир — равные веса включённых активов, приведённые к границам. М2 исключён и из оптимизированных вариантов, и из ориентира.

Excel-отчёты содержат веса девяти активов, реальные показатели, исходные официальные уровни и отдельный лист инфляции и М2. М2 присутствует только в исходных/макроэкономических данных. Рисунки скачиваются в SVG.

## Проверки

`npm test` проверяет арифметику, оптимизацию, независимость инвестиционных результатов от М2, инфляцию, временную проверку, сохранение сравнений, валидацию источников и снимков, ошибки сети и сертификаты. Playwright проверяет загрузку источников, все критерии, макрографики, Excel, сохранение/удаление, недоступность источников, GitHub Pages, языки, темы и мобильный вид. В рабочих данных и приложении генераторов нет; управляемые изменения данных используются только для математических тестов.

### Ковариация, короткие продажи и скользящая проверка

Оценка ковариации выбирается в настройках: выборочная с делителем `T−1` или OAS shrinkage, совместимая с формулой scikit-learn: эмпирическая ковариация `S` с делителем `T`, `center=tr(S)/p`, `alpha=mean(S²)`, `rho=min(1,(alpha+center²)/((T+1)*(alpha-center²/p)))`, при неположительном знаменателе `rho=1`. Итог: `(1−rho)S + rho*center*I`. OAS оценивается только по включённым активам; исключённые наблюдения не влияют на коэффициент сжатия или инвестиционный результат. Сила сжатия отображается рядом с результатом. Метод регуляризует ковариацию, но не удаляет выбросы. Доходности и риск всех портфелей используют их собственную сохранённую оценку.

Для ограничений применяется выпуклый active-set QP с проверкой допустимости; исходный решатель сохранён для стандартного режима. Короткие веса учитываются в исторической кривой и всех выгрузках, диаграмма заменяется столбцами со знаком. Объём длинных, коротких и совокупных позиций отображается отдельно. Нет платы за заём, комиссий, налогов, маржинальных ограничений и проверки доступности коротких продаж индекса или инструмента. Неположительный капитал вызывает явную ошибку.

Во вкладке «Графики» можно исключить актив с немедленным пересчётом текущего портфеля. Сохранённые варианты фиксируют свои данные, ковариацию, границы и веса; они продолжают сравниваться с новым текущим портфелем. Наборы v2 обратно совместимы с прежними официальными портфелями.

Rolling backtest настраивается во вкладке «Проверка»: окно обучения ≥12 доходностей, шаг 1–12 месяцев, минимум 12 проверочных месяцев. На каждом шаге обучение использует только предшествующее окно; следующие непересекающиеся участки объединяются в непрерывную кривую. Веса восстанавливаются ежемесячно, но переоцениваются только с указанным шагом. Последний участок может быть короче. Недостижимый в любом окне критерий исключается из всего результата с датой и причиной; проверочные участки не пропускаются. Волатильность результата — выборочная фактическая, ставка Шарпа — взвешенная по длине участков ставка на обучении. Обучающая доходность в итоговой таблице — такая же взвешенная средняя. Диаграмма показывает веса последнего окна; таблица окон и Excel содержат все даты, ставки, shrinkage и веса.
